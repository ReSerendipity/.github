# ADR-0015：执行方自主提交、推送、合并与 CI 监控

- 状态：Accepted
- 日期：2026-11-01
- 决策者：ReSerendipity（账号所有者）
- 相关：§17.2、§17.3、§17.4、ADR-0014（跨机并发）

## 背景

§17 已把「该推送的已推送、该合并的已合并、CI 盯到终态」写进完成定义，也在 §17.2 规定了
直推与分支 + PR 的选择，但没有一条明确禁止执行方在提交、推送、合并或 CI 监控前停下来询问
用户。实际交付中出现过「改完但未提交」「推送后把 CI 留给用户看」的形态，与完成定义冲突。
owner 的期望是：这些机械动作由执行方在任务结尾自主完成，不再逐步征询。

## 决策

1. **自主提交与推送**：本地检查全绿后，执行方按 §17.2 策略自行提交、推送；需要 PR 时自行开 PR。
2. **自主合并**：PR 场景下，必检全绿且无冲突时执行方自行合并（账号为单人 owner，PR 是门禁载体而非评审会议）；合并后删除源分支。
3. **自主 CI 监控**：push / PR 后由执行方自行盯到 `completed` 并读 `conclusion`，失败按 §17.3 闭环修复；不得把 CI 留给用户查看。
4. **唯一例外（仍须先询问）**：破坏性远端动作（重指向 / 删除 tag、force push、删除分支 / Release）、平台设置变更（分支保护、ruleset、Secrets、可见性）、凭据或权限缺失、任务明确要求先评审。
5. **完成判定**：未提交 / 未推送 / 应合并未合并 / CI 未到终态，只能报「未完成 + 阻塞原因」，不得以「待你确认」收尾。

## 后果

- 优点：任务结束时即达到可验证终态，用户不再充当 push 按钮与 CI 监视器。
- 优点：完成定义与执行动作一致，减少「已完成但远端无变化」的假交付。
- 代价：自主合并绕过人工复核；补偿控制是必检 + DCO + §17.3 失败闭环 + §17.5 并发边界与回滚约束。owner 可用「只做本地」指令覆盖。
- 观察项：多人协作者场景仍按 §17.2「非作者协作者」走 PR + 审批，不在本 ADR 的放行范围。

## 不采用

- 每步征询用户：把机械动作变成对话成本，且与完成定义冲突。
- 只提交不推送：工作区干净但远端无变化，CI 无法验证，等于未交付。
- 推送后不盯 CI：红留在 `main` 无人处置，违反 §17.3「合并后复核默认分支终态」。
