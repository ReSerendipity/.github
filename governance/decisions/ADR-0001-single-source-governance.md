# ADR-0001：治理单一事实来源（方案 A）

- 状态：Accepted
- 日期：2026-10-22
- 决策者：ReSerendipity（账号所有者）
- 相关：`governance/README.md`、§15

## 背景

治理正文曾分散在多个仓库：规范在 `.github`，各项目仓各自维护一份规则摘要，账号级健康文件又在另一处。任何一次规则调整都要在多仓重复编辑，且没有机制保证副本同步；实测出现过同一规则在两仓写法不一致的情况。

备选方案：

- 方案 B：在每个项目仓放完整规范副本，定期同步。
- 方案 C：不做单一来源，各仓自定规则，账号级只做最低安全约束。

## 决策

采用**方案 A**：`.github` 是账号级公共治理枢纽。

1. 规范正文只在 `governance/` 维护，是唯一事实来源。
2. 各项目仓根 `README.md` 只放**一行**引用，不复制正文。
3. `.github/` 目录只放平台执行用的自动化配置（workflows、scripts、健康文件），政策文档放 `governance/`。
4. 各仓 `docs/` 放项目自有标准，与账号级规范分层，不互相替代。

## 后果

- 改一处即全账号生效；引用方无需改动。
- 代价：离线或 fork 场景下，项目仓看不到完整规则，只能联网取。
- 代价：`.github` 成为单点，其 `main` 被误改会影响全部仓；以分支保护 + DCO + 周检补偿。

## 不采用

- 方案 B：副本必然漂移，且每次修订成本随仓数线性增长。
- 方案 C：账号级安全与法律义务会被项目自治架空。
