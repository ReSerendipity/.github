# ADR-0005：仓库备份——接受 GitHub 单远端

- 状态：Accepted
- 日期：2026-10-22
- 决策者：ReSerendipity（账号所有者）
- 相关：§3、§15.1 backup 轴

## 背景

按「远程 1 + 本地 1」的 2 副本模型，账号内 44 仓应有 44 个本地克隆。实测本机 `C:\Users\Doro\APP\repository` 只有 17 个克隆，其余 27 个仅在 GitHub 上。补齐需要约 2.6GB（可写工作副本）或 4.7GB（bare `--mirror` 只读镜像）。

## 决策

- **本轮不补本地副本**：44 仓继续以 GitHub 为唯一远端，现有 17 个克隆视为自然副本，不额外维护。
- 本决定登记为**已知风险**，不是「已完成」。
- 密钥类内容不适用本决定：`<项目名>-KeyBackup` 仍按 §3 双保险（远程私有仓 + 本地加密副本）。

## 后果

- 优点：不占用 2.6–4.7GB 磁盘，不引入镜像同步的维护成本与漂移风险。
- 代价：27 个仓只有一份。账号被盗、仓库误删、平台故障或区域封禁时**无法恢复**。
- 代价：恢复点目标（RPO）等于「GitHub 可用性」，没有独立于平台的第二份。

## 重新评估条件（任一命中即启动）

1. 新增含发布签名密钥的仓；
2. GitHub 账号发生安全事件；
3. 任一仓被误删且无本地副本；
4. 需要迁移到第二平台。

## 将来若要做

- 完整克隆 27 仓（约 2.6GB，可写、可离线提交）；
- 或 bare `--mirror` 37 仓（约 4.7GB，只读、可推送恢复）。

两者取舍：完整克隆便于继续工作但体积大；mirror 体积小、恢复快，但不能直接开发。
