# ADR-0014：多 Agent 并发的执行件与跨机边界

- 状态：Accepted
- 日期：2026-10-31
- 决策者：ReSerendipity（账号所有者）
- 相关：§17.2、§17.5、ADR-0008（单一本地 `AGENTS.md`）、ADR-0010（CI 远程化）

## 背景

§17.5（2026-10-23）用「开工前四查 + 判定矩阵」声明了多 agent 并发的应对办法，但落地有三处缺口：

1. **无决策记录**：§17 明文为账号级通用条款（§15.3 不裁剪），属改治理口径，却未按本仓红线「改治理口径先提 ADR」留痕；ADR-0001~0013 无一条覆盖并发。
2. **无执行件**：`.git/agent-session.lock` 的获取 / 心跳 / 释放、mtime 阈值、判定矩阵全靠人记；`check-governance-consistency.sh`、`audit-drift.py` 与 CI 都不检查 §17.5，`GOTCHAS.md` 也无并发冲突实例。
3. **跨机盲区**：锁、`git worktree list`、dirty mtime 都只存在于单个克隆。云电脑或另一台机器各有独立 `.git`，互相看不见，前两查在跨机并行时失效，而 §17.5 未写明边界。

## 决策

1. **判定口径不变**：四查项、10 / 30 分钟阈值、判定矩阵、「共享文件串行改」全部沿用 §17.5，本 ADR 不改变任何判据。
2. **新增只读执行件**：`.github/scripts/check-agent-session.sh` 机械化四查与矩阵，输出证据行与 `VERDICT: START | BRANCH | DEFER | LEGACY`。锁位于 `git rev-parse --git-common-dir` 下（linked worktree 共享，等价 §17.5 的 `.git/agent-session.lock`）；`--acquire --session <id>` 原子建锁、同 session 刷新心跳、过期锁可接管；`--release --session <id>` 只允许释放本 session 的锁，不匹配退 6。
3. **跨机边界入规范**：§17.5 增补「跨机边界」——本机三项检查只在当前克隆有效；云电脑 / 另一台机器并行时，唯一有效信号是远端 `refs/heads/agent/*` 分支与开放 PR，因此**一律分支 + PR，禁止直推**，以 PR 为串行点。
4. **载体分层**：并发判定是本地时序，CI 环境恒为干净单工作区，故**不做**「CI 当前并发」门禁。脚本的远端载体是 `negative-tests` 作业（活锁 / 过期锁接管 / 多 worktree / 远端 agent 分支 / 非 git 目录五类反例）加一次 CI 冒烟（干净 checkout 必须判 `START`、rc=0），与 ADR-0010 一致。
5. **心跳可持续**：长任务每 ≤10 分钟重跑 `--acquire --session <同 id>` 刷新心跳；超过 10 分钟会被判为不确定，超过 30 分钟判为过期。与 §17.5「活锁不删、过期锁核对后清理」配套。

## 后果

- 优点：§17.5 从纯声明变为可执行、有反例测试的检查；锁格式与释放规则有唯一实现，消除手写差异。
- 优点：跨机并行有了成文口径（远端分支 + PR），不再假设本地锁能跨机生效。
- 代价：本地多一条命令；跨机场景默认走 PR，比直推多一次合并步骤。
- 代价：10 / 30 分钟阈值固化进脚本，改阈值须同时改 §17.5 与脚本，并经新 ADR 留痕。
- 观察项：`ls-remote` 依赖网络，不可达时降级为「远端未知」并提示，不参与 `START` 判定，避免离线时误阻塞。

## 不采用

- 把并发判定做成 CI 门禁：CI 看不到本地锁、worktree 与 mtime，只会恒绿假通过。
- 把锁放到远端分支或独立仓库：多一次网络往返与凭据依赖，失败即阻塞开工，成本高于收益。
- 并入各仓 pre-push：账号级模板影响 17 个下游仓，误判成本高于收益。
- 只补 ADR 不补执行件：仍回到「靠人记」，缺口 2 不变。
- 承认本地锁跨机有效：与事实不符，会让云电脑并行误判为无并发而直推 `main`。
