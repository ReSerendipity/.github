# ADR-0023：§18 文档健康判据细化、首审结果归档、维持暂不解冻

- 状态：Accepted
- 日期：2026-11-20
- 决策者：ReSerendipity（账号所有者，本会话连续「同意」授权推进）
- 关联：修订 **§18.1**（六项必查的判据口径）、**§18.3**（审计方式与豁免）

## 背景

按 §18.3「首次全仓审查用只读脚本或手工清单完成」，2026-11-20 对 `C:\Users\Doro\APP\repository` 下 28 个本地克隆、1,321 篇活跃 Markdown 做了首轮审查。审查本身经历了两轮工具迭代：

- v1 报 725 孤儿 / 100 死链，绝大多数误报（未排除 `_archive`/`archive`/`local`，快照正则把叙事数字当计数）；
- v2 排除历史/生成/本地目录、收窄正则后，收敛到 21 死链 / 125 孤儿 / 1 处写死计数。

**这印证了 ADR-0022 的教训：验证工具本身也要被验证。** 未经验证的审查脚本给出的数字不可用。

进一步分析 v2 结果，发现主要问题不是「文档不健康」，而是**判据不清**：

1. **入链判据过窄**：`skills/<name>/references/*.md`、专题 `reports/`、目录级 README 都是合法局部文档，其入口是 skill 的 `SKILL.md` 或目录说明，不是根 README / docs 索引。它们被 v2 判为孤儿，实为假阳性。
2. **死链判据缺豁免**：指向 `local/**` 与根 `AGENTS.md` 的链接按 §7.1 本就不入库、CI 不可见，是**有意指向本地文档**的链接，不应判死链（但要求按 §18.1 标注）。
3. **快照判据缺历史豁免**：ADR 正文与 `_archive/**` 的历史计数是决策记录的既成事实，`decisions/README.md` 明确 ADR 不可改正文，不应要求其加「截至日期」。
4. **§18.3 的「暂不绑定 CI 门禁」依然正确**：在判据细化之前把六项绑上 CI，只会制造大批假红。

## 决策

1. **细化 §18.1 入链判据**：明确以下为合法入口，不计孤儿：
   - `skills/<name>/SKILL.md` 作为该 skill 目录下 `references/`、`scripts/` 文档的入口；
   - 目录级 `README.md` 作为同级专题文档（reports/、notes/）的入口；
   - `_archive/**`、`docs/adr/**`、`docs/audits/**` 的历史文档不参与入链检查。
   判红仅适用于「活跃 docs/ 下、非入口、且无任何路径引用」的孤儿。

2. **细化 §18.1 路径判据**：指向 `local/**`、`AGENTS.md`、`docs/agent-contract.md`（模板占位）的相对链接，只要按 §18.1 标注「本地文档，未随仓库发布」或属模板内相对引用，即豁免死链判定；其余死链照判。

3. **细化 §18.1 快照判据**：ADR 正文（`governance/decisions/**`）与 `_archive/**` 的历史计数豁免，不要求加「截至日期」；活跃文档的计数/版本/状态仍须带日期或指向单一来源。

4. **首审结果归档**：把《文档健康首次全仓审查报告》存入规范仓 `_archive/audits/2026-11/`，并在 `_archive/INDEX.md` 登记；按 §18.4「归档件自述」写明归档日、原路径、结论、正文未改。

5. **维持 §18.3「暂不绑定 CI 门禁」**：本轮只细化判据与归档证据，不升级任何门禁。

6. **重跑审查的实测结论（2026-11-20）**：按细化判据重跑后，写死计数从 1 → 0、命名 0 → 0（这两项判据细化生效）；但**死链/孤儿的绝对数字未下降**——原因是审查范围同时扩大（28→29 仓 / 1321→1447 篇，新出现一个 clone 中断的半成品目录 `demo/` 贡献 40 死链 + 大量孤儿，属无效样本应排除）。排除该半成品后，真实死链约 21 处（`.github` 2 处为模板/本地链接占位，`AI-Girls-Comic` 16 处为 `comic/docs/` 下相对路径基准错误，`SpiritPal` 3 处待核）。**结论：判据细化消除了「快照/命名」的假阳性，但没有、也不应一次性消除所有死链——其中相当一部分是真实的文档路径问题，须逐仓授权后清理。** 升级门禁的前置条件因此不是「假阳性归零」，而是「死链按仓分类并处置完毕」。

7. **逐仓取证后的最终结论（2026-11-20 二轮）**：对重跑后报出的死链逐仓核实，结论是**没有一处应当在本轮修改**：
   - `.github` 2 处：模板内相对链接（`CONTRIBUTING_TEMPLATE.md -> CODE_OF_CONDUCT.md`，落仓后解析）与本地 `AGENTS.md` 链接，已由本 ADR 第 2 条豁免；
   - `AI-Girls-Comic` 16 处：全部位于未跟踪的新文件（`comic/docs/`、`comic/scripts/` 整个目录是用户 WIP），按 §17.5 严禁触碰；
   - `SpiritPal` 3 处：位于 `references/llama.cpp/`（vendored 嵌套 git 仓），`/docs/backend/SYCL.md` 是上游文档站绝对路径，按 §7.2 / §12.5 归上游（见 GOTCHAS #62）。
   因此「死链按仓分类处置」的结果是：**三类均不属本仓可改范围**，不需要修改任何文档。审查工具的死链判据仍需补充两项豁免（嵌套 git 仓、以 `/` 开头的绝对路径），属后续工具改进项；工具误报不应通过改上游文件或用户 WIP 来"修复"。

8. **不把首审发现写进任何仓的 GOTCHAS**：这些是「待清理项」而非「踩坑」，除非将来真因某条死链导致事故，才按 §7.4 触发条件回写。（例外：审查工具自身的误判模式，如 GOTCHAS #62，符合 §7.4 第 6 触发条件「验证器自身有缺陷」，可以也应该记录。）

## 后果

- §18.1 三项判据（入链/路径/快照）补充豁免口径，减少机械审查的假阳性；判红门槛收窄到真实问题。
- 首审报告进入 `_archive/`，不进入默认读取面（§18.4）；活跃文档只保留一行摘要。
- §18.3 继续不绑门禁，避免大批假红；文档健康六项暂仍靠人工审查。
- 审查脚本（临时、工作区）不入库——判据细化后需重跑验证，但脚本本身不是规范资产。

## 不采用的方案

- **立即升级六项为 CI 门禁**：判据未细化、假阳性未消除，会把 skill references / 本地链接 / 历史 ADR 计数全判红。
- **按 v2 数字清理 146 处「问题」**：绝大多数是判据不清的假阳性，清理会造成无意义改动并可能破坏合法的局部文档结构。
- **把首审发现写入 GOTCHAS**：违反 §7.4 触发条件（踩坑/修 bug），这些是待办不是坑。
